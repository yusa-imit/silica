# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Move silica to Zig 0.16.0 with `zig build test` green in CI, apply the kingdom `io: Io` convention
to the public API, install a machine-checked Tiger Style floor (`zig build tidy`) and an assertion
baseline on the hot storage/transaction modules. Release v1.1.0.

## Why now

Phase 1 of `citadel/docs/ROADMAP.md` prescribes this plan first in every realm; silica comes after
zr, before zoltraak. The probe found **275 source errors** on 0.16 and 43 of 61 `src/` files
touching `std.fs`/`net`/`Thread`/`time`/`posix`; Tiger Style is worse — 12 asserts across 184k LOC,
212 `catch unreachable`, 41 files over 800 lines — so 001 installs a gate, not a retrofit.

## Out of scope

- Decomposing `sql/engine.zig` (43.2k lines) / `sql/executor.zig` (35.3k) — ROADMAP Phase 3.
- GIN redesign, MVCC version chains (v2.0), wiring `SlotManager` into `server.zig`, unadopted
  sailor features, swapping silica's `Io` for sirocco (ROADMAP Phase 2/3).
- Retrofitting the 212 `catch unreachable`, 104 `while (true)`, 7 `@panic` and 41 over-800-line
  files — 001 installs the gate and freezes the baseline, nothing more.

## Risks

- **Hard blocker**: nothing past the renames compiles until zuda v3.0.0 and sailor v3.0.0 exist —
  `zig build` dies inside *their* `build.zig`. Mitigation: `zig test src/main.zig` bypasses the
  dependency graph meanwhile; a 0.16 local package override covers a slipped tag.
- The `fs.cwd()` class (77 errors, 27 files) is an `Io`-threading rewrite, not a rename, and it
  lands in WAL and page-write paths where ordering and atomicity are correctness.
- `zig test src/main.zig` never reaches `server/*`, `cli.zig`, `tui.zig` — the true error count
  exceeds 275 and the fs/net items will grow once the build graph works.
- The tidy ratchet needs explicit `engine.zig`/`executor.zig` exemptions; a silent skip hides debt.
- Heavy suites (cross-compile, bench, fuzz, jepsen/stress) run in CI only after past local
  instability, so a migration bug they would catch surfaces late in the cycle.
- The old one-WAL-per-`Database.open()` concurrency limitation is unreconfirmed; the `Io.Mutex`
  conversion must not be read as fixing it.

## Done when

- CI on `main` green with Zig 0.16.0 (`gh run list --branch main --limit 1` shows success),
  `ci.yml` on `mlugg/setup-zig@v2`, `.minimum_zig_version = "0.16.0"`, cross-compile passing.
- `zig build tidy` is a dependency of `zig build test` and green.
- `grep -rn "std.fs.cwd\|std\.net\.\|std.Thread.Mutex\|GeneralPurposeAllocator" src/` returns
  nothing; `wip/wal-checkpoint-retention-phase2` is merged or split, decision recorded.
- `git tag --list v1.1.0` is non-empty and the GitHub release exists.

## Version impact

**MINOR** → v1.1.0. `io: Io` changes silica's public embedded API, which VERSIONING.md would make
MAJOR for a library with consumers — silica has none (service layer; the `REALM.md` consumer
registry is empty) and ROADMAP Phase 1 records silica as MINOR. Monotonic 1.0.1 → 1.1.0.
